## 2. Мета роботи

Пройти шлях від створення репозиторію й налаштування інфраструктури до консольної
програми, яку відтворено збирають і запускають на Windows, macOS та Ubuntu: Maven-проєкт
із JUnit 5, SpotBugs, виконуваним JAR, CI у GitHub Actions та версією з номером збірки.

## 3. Постановка задачі

Формат запису (`data/input.csv`, UTF-8, роздільник `;`):

`name:String; form:String; price:double; daysToExpire:int; prescription:boolean`

Показники:

1. кількість коректних записів;
2. середня ціна;
3. найменший термін придатності (`daysToExpire`);
4. кількість рецептурних препаратів (`prescription = true`).

Перевіряються: порожній рядок, кількість полів (5), порожні `name` і `form`, нечислові та
від'ємні `price` і `daysToExpire`, значення `prescription` (лише `true`/`false`).

## 4. Структура програми

Потік даних: `data/input.csv` → `FileReport.readLines` → `MedicineParser.parseAll`
(перевірка, список `Medicine` і список помилок) → `Stats.compute` →
`ReportFormatter.format` → консоль і `FileReport.writeReport`.

| Файл                  | Призначення                                        |
|-----------------------|----------------------------------------------------|
| `Main.java`           | аргументи, режими `--help`/`--version`, коди завершення |
| `FileReport.java`     | читання й запис файлів через `Path` і UTF-8        |
| `MedicineParser.java` | розбір і перевірка рядків                          |
| `Medicine.java`       | коректний запис                                    |
| `ParseResult.java`    | результат розбору                                  |
| `Stats.java`          | чотири показники                                   |
| `ReportFormatter.java`| форматування з `Locale.ROOT` і `%n`                |
| `BuildInfo.java`      | версія й номер збірки з `version.properties`       |

Рішення: ціна та термін перевіряються регулярними виразами до `parseDouble`/`parseInt`,
бо `Double.parseDouble` приймає `NaN`, `Infinity`, `1e3`; `Boolean.parseBoolean` не
використовується, бо будь-який інший текст він мовчки вважає `false`; на початку файла
ігнорується BOM; середнє обчислюється в `double`, порожній набір обробляється окремо.

## 7. Приклади роботи

Вхідні дані — `data/input.csv` (5 коректних і 7 хибних рядків). Консольний вивід і
файл `out/report.txt` збігаються:

```text
Звіт: аптека
Коректних записів: 5
Середня ціна: 165.69 грн
Найменший термін придатності: 60 дн.
Рецептурних препаратів: 2
Пропущено рядків: 7
  Рядок 6: порожній рядок
  Рядок 7: ціна не є числом: 'ціна'
  Рядок 8: від'ємна ціна: -15.00
  Рядок 9: від'ємний термін придатності: -5
  Рядок 10: очікується 5 полів, знайдено 4
  Рядок 11: порожня назва препарату
  Рядок 12: ознака рецепта має бути true або false: 'можливо'
```

Ручна перевірка середньої ціни: (45.50 + 132.00 + 98.75 + 32.20 + 520.00) / 5 = 165.69.

`java -jar target/lab01-1.0.0.jar --version` → `1.0.0+local` (локально), `1.0.0+[N]` (CI).

## 11. Відповіді на контрольні питання

> Чернетка; перепишіть власними словами.

1. `pom.xml` описує проєкт для Maven: координати, версію Java, кодування, залежності та плагіни збірки.
2. `test` компілює й запускає тести; `package` формує JAR; `verify` йде після пакування й виконує перевірки якості (тут SpotBugs). Кожна фаза запускає всі попередні.
3. Wrapper завантажує зафіксовану версію Maven, тож збірка однакова в усіх без глобальної установки Maven.
4. `main` — точка входу, з якої JVM починає виконання програми.
5. Примітивний тип зберігає саме значення (`int`, `double`), `String` — посилальний тип-об'єкт із методами.
6. `int / int` відкидає дробову частину; потрібно хоча б один операнд привести до `double`.
7. `Integer.parseInt("abc")` кидає `NumberFormatException`.
8. Мовчазний пропуск ховає втрату даних і псує довіру до показників; потрібні номер рядка й причина.
9. З `-1` порожнє останнє поле зберігається як порожній рядок; без нього кінцеві порожні поля відкидаються.
10. `Path.of` сам підставляє роздільник поточної ОС; `"data\\input.csv"` працює лише на Windows.
11. Кодування за замовчуванням залежить від ОС; явний UTF-8 дає однаковий результат усюди, зокрема для українських літер.
12. `%n` — роздільник рядків платформи (CRLF у Windows, LF в Unix); `\n` завжди LF.
13. Кількість полів, порожні `name`/`form`, нечислові й від'ємні `price`/`daysToExpire`, `prescription` лише `true`/`false`.
14. Тест на набір із відомим середнім (`StatsTest.averageKeepsFractionalPart`), тест із пропущеними рядками, що не мають змінювати середнє, порожній набір.
15. Статичний аналізатор знаходить типові дефекти в байт-коді без запуску програми.
16. GitHub Actions автоматично збирає й тестує кожну зміну на трьох ОС та публікує артефакти.
17. Версія описує стан продукту, номер збірки — конкретний запуск CI. Знак `+` у SemVer відділяє метадані збірки; `1.0.0.42` читалося б як нова версія з чотирьох чисел.
18. Заголовок, кроки відтворення, очікуваний і фактичний результат, за потреби — вхідні дані й середовище.
19. Інструмент і версію, внесок автора й ШІ, як перевірено результат, джерела та підтвердження відповідальності й розуміння коду.
20. DevOps консультує щодо збірки, CI й помилок інфраструктури; Валідатор складає крайові випадки й оформлює дефекти, не виправляючи код.
