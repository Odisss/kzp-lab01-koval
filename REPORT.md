## 1. Тема, номер і варіант

- Тема: об'єктно-орієнтована обробка даних у Python — класи, `@property`, `@dataclass`,
  спеціальні методи, підтипи, `Protocol`, pytest, ruff, wheel.
- Варіант 11 (незмінний), предметна область «Аптека». Базовий клас `Medicine`, підтипи
  `PrescriptionMedicine` і `FreeMedicine`, спільна операція `availability_score()` за
  рецептом і терміном, підсумок — препарати з близьким терміном.
- Поля CSV не змінилися: `name,form,price,days_left,prescription`.
- ОС: Windows 11, Python 3.12.6, VS Code, PowerShell.
- Репозиторій: <https://github.com/Odisss/kzp-lab01-koval>, гілка `lab07`, версія `1.6.0`,
  тег `v1.6.0`.

## 2. Мета роботи

Перетворити словникові записи ЛР № 6 на об'єкти з власною поведінкою: перенести
перевірку значень у властивості, відмінну поведінку — у підтипи, підсумок — у незмінний
`@dataclass`, а аналіз побудувати на спільному протоколі без перевірок конкретного класу.
Зовнішній формат звіту має лишитися тим самим.

Досягнутий стан: новий пакет `kzp_lab07` (`models`, `errors`, `loader`, `analysis`,
`reporting`, `cli`), пакет `kzp_lab06` збережено без змін як еталон словникової моделі.
127 тестів pytest проходять (45 тестів ЛР № 6 без змін + 82 нові), `ruff check` і
`ruff format --check` чисті, wheel `kzp_lab07-1.6.0` збирається й дає той самий звіт, що
й ЛР № 6. Виконано також завдання із зірочкою: протокол із властивостями й методом і
власний контекстний менеджер запису звіту з перевіркою закриття під час винятку.

## 3. Чому новий пакет, а не зміна `kzp_lab06`

Методичка задає структуру `src/kzp_lab07/` з модулем `models.py`. Пакет `kzp_lab06`
залишено недоторканим: його 45 тестів і еталон `data/lab06-expected-report.txt` проходять
так само, як у ЛР № 6, а наявність обох реалізацій в одному дистрибутиві дає змогу
автоматично перевіряти еквівалентність звітів (розділ 9). Дистрибутив перейменовано на
`kzp-lab07`, він містить обидва пакети й дві консольні команди: `kzp-lab06` і `kzp-lab07`.

## 4. Класи, поля, підтипи та спільна операція

| Клас | Поля / властивості | Поведінка |
|------|--------------------|-----------|
| `Medicine` | `name`, `form`, `price`, `days_left` (property + setter), `prescription` (лише читання) | `is_expiring(max_days)`, `availability_score()` (оголошення), `__str__`, `__repr__`, `__eq__`; `__hash__ = None` |
| `PrescriptionMedicine(Medicine)` | `PRESCRIPTION = True` | `availability_score() = min(days_left, 180) / 180 · 60` |
| `FreeMedicine(Medicine)` | `PRESCRIPTION = False` | `availability_score() = min(days_left, 365) / 365 · 100` |
| `Available(Protocol)` | `name`, `form`, `price`, `days_left`, `prescription` | `availability_score()` |
| `ReportSummary` (`@dataclass(frozen=True)`) | `total`, `max_days`, `selected`, `selected_price`, `forms`, `count_by_form`, `prescription_count`, `nearest`, `average_price`, `availability` | автоматичні `__init__`, `__repr__`, `__eq__`, `__hash__` |
| `ReportWriter` | `path`, `closed` | `__enter__` / `__exit__`: тимчасовий файл → `os.replace` |

Індекс доступності — число 0–100. Безрецептурний препарат досягає 100 балів за року
терміну. Рецептурний — не більше 60 балів (потрібен рецепт), але повного значення вже за
180 днів (курс лікування рідко довший). Нульовий термін в обох підтипах дає 0. Індекс
округлюється до двох знаків.

Інваріанти перевіряються в setter-ах, тому діють і в конструкторі, і при пізнішій зміні:

| Поле | Правило | Помилка |
|------|---------|---------|
| `name`, `form` | рядок, непорожній після `strip()`; `form` — нижній регістр | `TypeError` / `ValueError` |
| `price` | число (не `bool`), скінченне, `>= 0`; зберігається як `float` | `TypeError` / `ValueError` |
| `days_left` | `int` (не `bool`), `>= 0` | `TypeError` / `ValueError` |

```python
@price.setter
def price(self, value: float) -> None:
    """Встановлює скінченну невід'ємну ціну."""
    if isinstance(value, bool) or not isinstance(value, int | float):
        raise TypeError("поле price має бути числом")
    if not math.isfinite(value):
        raise ValueError("поле price має бути скінченним числом")
    if value < 0:
        raise ValueError("поле price не може бути від'ємним")
    # Записується внутрішнє поле, тому setter не викликає сам себе.
    self._price = float(value)
```

Ознака рецепта не є полем стану: її визначає підтип (атрибут класу `PRESCRIPTION`), тож
неможливо створити «безрецептурний» об'єкт із `prescription = True`.

## 5. Спеціальні методи та впорядкування

```text
>>> m = FreeMedicine("Цитрамон", "таблетки", 32.2, 12)
>>> str(m)
'Цитрамон (таблетки) — 12 дн., 32.20 грн'
>>> repr(m)
"FreeMedicine(name='Цитрамон', form='таблетки', price=32.2, days_left=12)"
>>> m == FreeMedicine("Цитрамон", "таблетки", 32.2, 12)
True
>>> m == PrescriptionMedicine("Цитрамон", "таблетки", 32.2, 12)
False
>>> m.__eq__("Цитрамон")
NotImplemented
```

`__eq__` повертає `NotImplemented` для чужого типу й вимагає збігу конкретного підтипу.
Оскільки об'єкт змінюваний, `__hash__ = None`: його не можна випадково покласти в
множину чи використати як ключ, а потім змінити. Порядок задано не через `__lt__`, а
ключами в `analysis`: `expiry_key` (термін, назва) — для звіту, `availability_key`
(індекс, назва) — для ранжування. Критерій сортування залежить від задачі, а не є сталою
властивістю препарату.

## 6. Протокол і качина типізація

```python
@runtime_checkable
class Available(Protocol):
    # також властивості name, form, price
    @property
    def days_left(self) -> int: ...
    @property
    def prescription(self) -> bool: ...
    def availability_score(self) -> float: ...
```

Функції `analysis` типізовані через `Available` і викликають лише його члени:

```python
def rank_by_availability(items: Iterable[Available]) -> list[tuple[str, float]]:
    return [
        (item.name, item.availability_score())
        for item in sorted(items, key=availability_key)
    ]
```

У `analysis.py` немає жодного `isinstance` чи `type(...)`. Тест
`test_duck_typing_without_inheritance` передає у `least_available`, `select_expiring` і
`make_summary` об'єкт класу `StockItem`, який не наслідує `Medicine`, але має ті самі
властивості й метод, — функції працюють без змін.

Підтип обирається один раз, на межі завантаження, через словник:

```python
_SUBTYPES: dict[bool, type[Medicine]] = {
    True: PrescriptionMedicine,
    False: FreeMedicine,
}
```

`loader` перетворює текст на типи (`float`, `int`, `bool`) з власними повідомленнями, а
діапазони перевіряє конструктор. `ValueError`/`TypeError` моделі обгортаються в
`DataError` з номером рядка й першопричиною (`raise ... from error`).

## 14. Відповіді на контрольні питання

1. Клас описує структуру й поведінку (`FreeMedicine`), екземпляр — конкретний препарат зі
   своїм станом (`FreeMedicine("Цитрамон", "таблетки", 32.2, 12)`).
2. `__init__` виконується після створення екземпляра й встановлює початковий стан; тут
   він присвоює властивості, тож одразу спрацьовують setter-и. `self` — посилання на
   поточний екземпляр, перший параметр методу.
3. Щоб значення виглядало як поле, але читання й запис проходили через метод: setter
   перевіряє інваріант (`price >= 0`) і при створенні, і при пізнішій зміні.
4. Присвоєння `self.price = value` всередині setter-а знову викликало б setter — нескінченна
   рекурсія. Тому значення зберігається у внутрішньому `self._price`.
5. Генерує `__init__`, `__repr__`, `__eq__`, а з `frozen=True` (і типовим `eq=True`) — ще й
   `__hash__` і заборону присвоювання полям.
6. Щоб підсумок не можна було змінити після обчислення: він порівнюється, хешується й
   передається у звіт як значення. Спроба присвоєння — `FrozenInstanceError`.
7. `__str__` — коротке подання для читача (`Цитрамон (таблетки) — 12 дн., 32.20 грн`),
   `__repr__` — однозначне діагностичне з назвою класу й полями.
8. Повертати `NotImplemented`, щоб Python спробував симетричне порівняння з іншого боку,
   а за його відсутності `==` дав `False`.
9. Коли критерій залежить від задачі: звіт упорядковує за терміном, ранжування — за
   індексом. Ключі `expiry_key` і `availability_key` у `analysis` простіші за повний набір
   методів порівняння й не нав'язують препарату «природний» порядок.
10. Викликає наступну реалізацію методу в MRO; у підтипах `super().__init__` (успадкований
    `__init__`) виконує спільні перевірки базового класу.
11. MRO — порядок пошуку атрибутів у ієрархії (`FreeMedicine → Medicine → object`). За
    множинного наслідування `super()` веде не обов'язково до «батька», тому порядок
    потрібно знати, щоб ініціалізація кожного класу виконалася рівно один раз.
12. Важливо, що об'єкт уміє (має `days_left`, `availability_score()`), а не його клас:
    `analysis` приймає навіть `StockItem`, що не наслідує `Medicine`.
13. Описує контракт явно й перевірно для інструментів типізації без вимоги наслідування;
    з `runtime_checkable` можна перевірити наявність членів через `isinstance`.
14. Інакше кожен новий підтип вимагав би змін у всіх функціях аналізу; формула має
    залишатися в підтипі, а аналіз — викликати спільний метод.
15. У `loader`, на межі завантаження: там рядок CSV перетворюється на типи й обирається
    підтип; далі програма працює лише з коректними об'єктами.
16. Імпорт у тесті або з іншого модуля не повинен читати аргументи, писати файли й
    завершувати процес; тому `main()` викликається лише під `if __name__ == "__main__"`.
17. Setter (коректне, нульове, граничне, помилкове значення й незмінність стану),
    незмінність і рівність dataclass, `__str__`/`__repr__`/`__eq__`, різні результати
    підтипів, робота спільних функцій з обома підтипами й чужим класом, коди CLI.
18. pytest перевіряє поведінку, ruff — помилки й стиль/форматування, wheel — що пакет
    правильно описаний і працює після встановлення в чисте середовище.
19. Порожній файл і файл лише з заголовком; нульові ціна й термін; термін понад горизонт
    індексу; дублікат запису; нічия найменшого терміну; хибний тип, від'ємне, `nan`,
    відсутнє й зайве значення; невідомий стовпець; збій запису звіту.
20. Назви класів, поля, підтипи й спільну операцію; формули; старий словниковий і новий
    об'єктний результати та їх порівняння; команди й результати pytest, ruff, wheel, CI;
    Issues, PR і тег.

## 15. Висновки

Словникові записи ЛР № 6 замінено об'єктною моделлю: базовий клас `Medicine` тримає
інваріанти у властивостях із setter-ами, підтипи `PrescriptionMedicine` і `FreeMedicine`
мають власні формули `availability_score()`, а аналіз працює через протокол `Available`
без жодної перевірки конкретного класу. Підсумок став незмінним `ReportSummary`. Звіт
лишився побайтово тим самим, що підтверджують тести еквівалентності для кількох CSV і
порогів; нова опція `--scores` показує результат поліморфної операції. Запис звіту
виконує власний контекстний менеджер, який не залишає частково записаного файла.
Поведінку закріплено 127 тестами, якість — ruff, пакет перевіряється wheel-збіркою в CI
на трьох ОС.
