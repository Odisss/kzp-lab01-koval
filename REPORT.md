# Звіт до лабораторної роботи № 5

Параметризоване сховище, винятки й CSV-експорт у Java-проєкті. Звіти попередніх робіт:
[`REPORT-lab01.md`](REPORT-lab01.md), [`REPORT-lab02.md`](REPORT-lab02.md),
[`REPORT-lab03.md`](REPORT-lab03.md), [`REPORT-lab04.md`](REPORT-lab04.md).

## 1. Тема, номер і варіант

- Тема: параметризоване сховище, власний виняток, анотації, рефлексія й CSV-експорт.
- Варіант 11 (незмінний), предметна область «Аптека».
- Клас запису варіанта: `MedicineRecord` (поля `name`, `form`, `price`, `expiresOn`,
  `prescription`); CSV-стовпці: назва, форма, ціна, придатність, рецепт; ключ round-trip —
  назва + форма.
- ОС: Windows 11, JDK 21, VS Code.
- Репозиторій: <https://github.com/Odisss/kzp-lab01-koval>, гілка `lab05`, версія `1.4.0`.

## 2. Мета роботи

Замінити пряме зберігання коректних записів у списку на параметризоване сховище
`Repository<T>`, описати CSV-стовпці анотацією `@CsvColumn`, реалізувати універсальний
рефлексивний експортер і документний парсер, обробляти помилки власним винятком
`DataStorageException` із причиною та довести round-trip «об'єкт → CSV → об'єкт».

Досягнутий стан: звіт для контрольного файла не змінився, усі 79 попередніх тестів
проходять, додано 33 нові (разом 112), `verify` зі SpotBugs проходить, JAR створюється,
CI на трьох ОС зелений.

## 3. Модель даних варіанта

| Поле Java | Тип | `@CsvColumn` | Джерело в моделі ЛР № 1–4 |
|-----------|-----|--------------|----------------------------|
| `name` | `String` | назва | `Medicine.name()` |
| `form` | `String` | форма | `Medicine.form()` |
| `price` | `double` | ціна | `Medicine.price()` |
| `expiresOn` | `LocalDate` | придатність | сьогодні + `Medicine.daysToExpire()` |
| `prescription` | `MedicineKind` (enum) | рецепт | `Medicine.kind()` |

Поліморфна модель (`Medicine`, `PrescriptionMedicine`, `FreeMedicine`) не змінилася.
`MedicineRecord` — окремий плоский незмінний клас для збереження: у ньому календарна дата
замість «днів до кінця», а категорія — enum. Перетворення в обидва боки:
`MedicineRecord.from(Medicine, today)` і `toMedicine(today)`; рецептурний чи
безрецептурний підтип відновлюється з enum.

Інваріанти `MedicineRecord` (порушення — `IllegalArgumentException` або
`NullPointerException` у конструкторі): назва й форма непорожні; ціна скінченна, не
менша за 0, для рецептурного — більша за 0; дата й категорія не `null`.

`equals` і `hashCode` узгоджені й враховують усі п'ять полів; поля `final`, тому запис
можна безпечно класти в `HashSet` і використовувати ключем карти.

## 4. `Repository<T>`

```java
public final class Repository<T> {
    private final List<T> items = new ArrayList<>();
    public void add(T item) { items.add(Objects.requireNonNull(item)); }
    public void addAll(List<? extends T> newItems) { ... }
    public List<T> all() { return List.copyOf(items); }
    public List<T> find(Predicate<? super T> condition) { ... }
    public int size() { ... }
}
```

У `Main` коректні препарати після розбору додаються в `Repository<Medicine>`, а
показники, `--availability`, `--queries` і `--export` працюють зі знімком `all()`.
Raw type ніде не використовується. `find` приймає `Predicate<? super T>`, тому для
`Repository<Medicine>` підходить і `Predicate<Object>`. Знімок незмінний і не залежить
від наступних `add` (тест `snapshotIsImmutableAndDetached`).

## 5. Анотація та рефлексія

```java
@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.FIELD)
public @interface CsvColumn {
    String value();
}
```

`CsvExporter.annotatedFields(type)`:

1. проходить клас і його суперкласи до `Object`, бере `getDeclaredFields()`;
2. залишає нестатичні поля з `@CsvColumn`;
3. сортує за Java-іменем поля (за рівності — за іменем класу);
4. для кожного поля викликає `trySetAccessible()`; якщо доступ заборонено або полів немає,
   кидає `DataStorageException`.

Значення читається через `field.get(record)` і перетворюється на текст
`String.valueOf`; `null` записується порожнім полем. Експортер не містить назв класів
варіанта й умов за підтипом: тест експортує два довільні тестові класи `Point` і
`NamedPoint extends Point` (поля суперкласу теж потрапляють у CSV).

Фактичний заголовок для `MedicineRecord` (порядок за іменами
`expiresOn < form < name < prescription < price`):

```text
придатність,форма,назва,рецепт,ціна
```

## 6. Формат CSV і запис файла

- Перший рядок — заголовки з `@CsvColumn`, далі значення в тому самому порядку.
- Кодування UTF-8 і під час запису (`Files.writeString(path, text, UTF_8, CREATE,
  TRUNCATE_EXISTING, WRITE)`), і під час читання (`Files.readString(path, UTF_8)`).
- Батьківський каталог створюється `Files.createDirectories`; шлях — `Path.of`.
- Поле з комою, лапкою, `\n` або `\r` береться в лапки, лапка подвоюється.
- Роздільник рядків — `System.lineSeparator()`; парсер приймає `\n` і `\r\n`, BOM
  пропускає, тому файл з Windows читається на Linux і macOS і навпаки.
- Дата — ISO `yyyy-MM-dd`, число — `Double.toString` (крапка незалежно від локалі),
  enum — ім'я константи.

Екранований рядок (кома й лапки в назві):

```text
2027-11-18,сироп,"Вітаміни ""Сонечко"", дитячі",FREE,89.9
```

Multiline-поле (з тесту `escapedRowsInFile`) займає два фізичні рядки, але є одним
записом:

```text
2027-06-01,мазь,"Мазь
для суглобів",FREE,0.0
```

## 7. Читання та round-trip

`CsvParser.parseDocument` — машина станів над усім текстом: стан «в лапках» відрізняє
кому й перенесення рядка як дані від роздільників структури. Повертає список записів, а
не фізичних рядків. `split(",")` для рядка `A-03,ART,"Карти, що говорять",1988` дає 5
частин замість 4 (перевірено в `CsvParserTest`).

`MedicineCsvStore.read`: читає файл, розбирає, перевіряє, що заголовок збігається з
`CsvExporter.header(MedicineRecord.class)`, і відновлює кожен запис через
`MedicineRecord.fromFields` (дата — `LocalDate.parse`, ціна — `Double.parseDouble`,
категорія — `MedicineKind.valueOf`, далі конструктор з інваріантами).

Запуск на `data/lab05.csv` (6 коректних записів, один із комою й лапками, і 1 хибний
рядок вхідного формату):

```text
> java -jar target\lab01-1.4.0.jar --input data\lab05.csv --export out\medicines.csv
Звіт: аптека
Коректних записів: 6
Середня ціна: 153.06 грн
Найменший термін придатності: 60 дн.
Рецептурних препаратів: 2
Пропущено рядків: 1
  Рядок 7: ціна не є числом: 'ціна'
Звіт записано: out\report.txt
CSV записано: out\medicines.csv (6 записів)
Round-trip: відновлено 6 записів, рівні: так
```

`out\medicines.csv` (дати відлічено від 2026-11-18):

```text
придатність,форма,назва,рецепт,ціна
2028-01-12,таблетки,Парацетамол,FREE,45.5
2027-09-14,капсули,Амоксицилін,PRESCRIPTION,132.0
2027-05-17,гель,Ібупрофен,FREE,98.75
2027-01-17,таблетки,Цитрамон,FREE,32.2
2027-02-16,розчин,Інсулін,PRESCRIPTION,520.0
2027-11-18,сироп,"Вітаміни ""Сонечко"", дитячі",FREE,89.9
```

«Рівні: так» означає дві перевірки: список `MedicineRecord` до запису дорівнює списку
після читання (`equals` за всіма полями, у тому самому порядку), і препарати, відновлені
з CSV через `toMedicine(today)`, дорівнюють препаратам зі сховища (той самий підтип,
ціна, днів до кінця). Відновлення за ключем варіанта (назва + форма):

| Ключ | До експорту | Після імпорту |
|------|-------------|---------------|
| Інсулін\|розчин | 520.0, 2027-02-16, PRESCRIPTION | 520.0, 2027-02-16, PRESCRIPTION |
| Вітаміни "Сонечко", дитячі\|сироп | 89.9, 2027-11-18, FREE | 89.9, 2027-11-18, FREE |

## 8. Помилки

`DataStorageException extends Exception` (checked) має конструктори `(message)` і
`(message, cause)`. Виняток не поглинається: `Main` друкує повідомлення й увесь ланцюг
`getCause()` і повертає код 1.

| Рівень | Приклад | Реакція |
|--------|---------|---------|
| Модель | порожня назва, від'ємна ціна, рецептурний за 0 грн | `IllegalArgumentException` у конструкторі; у CSV — `DataStorageException` з цією причиною |
| Формат | 4 поля замість 5, незакрита лапка, хибний заголовок | `DataStorageException` без cause, з номером запису |
| Значення | `дорого` у полі ціни, `МОЖЛИВО` у полі рецепту, `31.12.2027` | `DataStorageException`, cause `NumberFormatException` / `IllegalArgumentException` / `DateTimeParseException` |
| Файл | немає файла, батьківський шлях — файл | `DataStorageException`, cause `NoSuchFileException` / `IOException` |
| Рефлексія | клас без полів з `@CsvColumn`, доступ заборонено | `DataStorageException` з поясненням |

Порожній файл (0 байтів) і файл лише із заголовком — допустимі й дають порожній список
(контракт `MedicineCsvStore`).

Приклад помилки:

```text
> java -jar target\lab01-1.4.0.jar --import data\lab05-invalid.csv
Помилка: Запис 2: поле 5 (ціна): не є числом 'дорого'
  причина: java.lang.NumberFormatException: For input string: "дорого"
```

## 13. Відповіді на контрольні питання

1. Одне сховище працює з будь-яким типом, а компілятор перевіряє, що додаються й
   повертаються об'єкти саме цього типу, без приведень.
2. Raw type `Repository` вимикає перевірку типів: можна додати будь-що, а помилка
   з'явиться лише під час виконання як `ClassCastException`.
3. Щоб передавати умову для `T` або його супертипу (`Predicate<Object>`,
   `Predicate<Medicine>` для сховища підтипу).
4. Щоб зовнішній код не змінив внутрішній список сховища в обхід `add`.
5. Виняток, який компілятор вимагає обробити або оголосити в `throws`. Доречний для
   відновлюваних збоїв: немає файла, пошкоджений CSV.
6. Щоб не загубити технічну першопричину (`IOException`, `NumberFormatException`) і
   могти її діагностувати.
7. `Path.of` будує шлях з правильним роздільником для ОС; `Files` дає готові операції
   з явним кодуванням і зрозумілими винятками.
8. Інакше використовується кодування ОС за замовчуванням, і файл, записаний в одній
   системі, в іншій прочитається з кракозябрами.
9. `RUNTIME` залишає анотацію доступною рефлексії під час виконання; `FIELD` дозволяє
   ставити її лише над полями.
10. Анотація — лише метадані; поведінку реалізує код, який її читає (експортер).
11. `getDeclaredFields()` повертає всі поля саме цього класу, включно з приватними, але
    без успадкованих; `getFields()` — лише публічні, зате й успадковані.
12. Доступ до приватного поля може бути заборонено (наприклад, модулями Java); результат
    `false` потрібно перетворити на зрозумілу помилку.
13. Порядок `getDeclaredFields()` не гарантується специфікацією; без сортування заголовок
    міг би відрізнятися між JVM.
14. Кома всередині лапок теж розділить поле, а перенесення рядка в лапках розірве запис.
15. Поле береться в подвійні лапки, лапка всередині подвоюється.
16. Без жодного запису неможливо дізнатися клас, а отже й заголовок.
17. Експортер не знає домену й лише читає поля; `fromFields` знає типи (дата, число,
    enum) та інваріанти свого класу.
18. Модель, формат, значення, файл, рефлексія (таблиця в розділі 8).
19. Що запис і читання не втрачають і не змінюють жодного значення, включно з комами,
    лапками, перенесеннями, датами, числами й enum, і зберігають порядок.
20. Помилка зникає безслідно: програма продовжує роботу з хибними даними, а причину
    неможливо знайти.

## 14. Висновки

Коректні записи зберігаються в параметризованому `Repository<T>`, збереження описано
анотацією `@CsvColumn`, а універсальний рефлексивний експортер записує будь-який клас
з анотованими полями в UTF-8 CSV з коректним екрануванням. Документний парсер і
`MedicineRecord.fromFields` відновлюють записи, round-trip на даних варіанта дає рівні
об'єкти. Помилки всіх рівнів подаються власним винятком без втрати першопричини.
Попередній звіт і тести не змінилися.
